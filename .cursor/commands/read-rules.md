# Протокол разработки

## Перед началом любой работы

### 1. Memory bank `rules/`

**Не читай всю папку.** Точка входа — `rules/index.md`. Дальше только нужная ветка через её `index.md`.

**Всегда:**
- `rules/index.md`
- `rules/basics/project_structure.py` — если трогаешь структуру/слои/эндпоинты

**По типу задачи (через index папки, не всё подряд):**
- Python в `src/` → `rules/code/index.md` → `python.md`
- Тесты → `rules/code/index.md` → `tests.md`
- SQL / схема → `rules/db/index.md` → `db.mdc`
- Фича (auth, tasks, s3, nginx, notifications) → `rules/development_plans/index.md` → папка фичи → статус в плане

### 2. Полнота контекста
- [ ] Требования понятны
- [ ] Прочитан только релевантный индекс + файл
- [ ] Статус плана сверен с кодом
- [ ] Есть пример в кодовой базе

## Во время работы

- Паттерны из соседнего кода того же слоя, не изобретай параллельный стиль.
- Решения «почему» — в план фичи, не только в diff.
- Контекст: канонические секции важнее примеров; потерялся → снова `rules/index.md`.
