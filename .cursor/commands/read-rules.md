# Протокол разработки

## Перед началом любой работы

### 1. Загрузи контекст `rules/`
Прочитай все релевантные файлы из `rules/` в зависимости от типа задачи:

**Всегда читай:**
- `rules/index.md` — навигация и обзор структуры

**По типу задачи:**
Проверь по навигационному файлу наличие нужной тебе информации и внимательно изучи её
Например:
- **Python код:** `python.md`
- **Терминология:** `terms.md`

### 2. Проверь полноту контекста
- [ ] Понимаю требования задачи
- [ ] Знаю, какие правила применяются
- [ ] Вижу перекрёстные ссылки между правилами
- [ ] Нашёл примеры в кодовой базе

---

## Во время работы

### Следуй установленным паттернам

### Отслеживай изменения и решения
- Регулярно обновляй правила в соответствии с нашими договорённостями
- Документируй **почему** приняты решения (не только что сделано)
- Помечай неоднозначные случаи для уточнения

### Следи за контекстным окном
- Приоритизируй чтение канонических разделов над примерами
- Перечитывай `rules/index.md` при потере контекста
- Используй перекрёстные ссылки для навигации между правилами
- Отслеживай, какие файлы уже в контексте

---

## После значительных изменений

### Обнови релевантную документацию
### Обеспечь консистентность между файлами
- [ ] Перекрёстные ссылки актуальны (относительные пути корректны)
- [ ] Нет противоречий между файлами правил
- [ ] Примеры соответствуют текущим паттернам
- [ ] Терминология согласована с `rules/basics/terms.md`

### Подготовься к сбросу контекста
Перед потерей контекста задокументируй:
- **Текущее состояние:** Что сделано, что осталось
- **Ключевые решения:** Почему выбраны конкретные подходы
- **Обновления правил:** Какие правила нужно обновить на основе этой работы
- **Следующие шаги:** Чёткие действия для продолжения
