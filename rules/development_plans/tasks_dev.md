## Сущность «Задача»

### Поля

| Поле | Обязательность | Описание |
|------|----------------|----------|
| `title` | да | До 50 символов. Создание задачи = создание title |
| `description` | нет | Текст, редактируется после создания |
| `priority` | нет | `null` (без приоритета), `low`, `medium`, `high` |
| `due_date` | нет | `TIMESTAMPTZ`. Дата обязательна для планирования; время опционально |
| `status` | да | `active`, `completed` |
| `list_id` | да* | Физический список задачи (* у подзадачи наследуется от родителя) |
| `parent_id` | нет | Ссылка на родительскую задачу (подзадача) |
| `previous_list_id` | нет | Список до soft delete (для restore из корзины) |
| `deleted_at` | нет | Soft delete (корзина) |

### Аудит

`created_at`, `updated_at`, `completed_at` — достаточно для MVP.

### Подзадачи

- Та же сущность, что и задача (`parent_id`).
- Наследуют `list_id` от родителя; при перемещении родителя — каскад на всех потомков.
- `due_date` при создании — **без даты** (не копируется автоматически с родителя).
- Статус по умолчанию — `active`.
- Могут существовать **без родителя** (самостоятельная задача).
- Учитываются в лимите задач списка (корневые + подзадачи).
- Располагаются там же, где родитель (тот же `list_id`).

### Каскады

| Действие | Поведение |
|----------|-----------|
| Complete родителя | Все подзадачи → `completed` |
| Все подзадачи completed | Родитель → `completed` (авто) |
| Soft delete родителя | Все подзадачи → корзина |
| Move родителя | Все подзадачи следуют за `list_id` |

## Списки

### Типы

| Список | Хранение | Лимит задач | Назначение |
|--------|----------|-------------|------------|
| **Входящие** | Физический (системный) | 100 | Задачи, ещё не распределённые по пользовательским спискам; стандартное место для новых задач |
| **Сегодня** | Виртуальный | — | Фильтр: `due_date` = календарный «сегодня» в TZ пользователя |
| **Следующие 7 дней** | Виртуальный | — | Фильтр: `due_date` ∈ [today, today+7] по календарю в TZ пользователя (**включая «Сегодня»**) |
| **Выполненные** | Виртуальный | — | Фильтр: `status = completed`. Задача остаётся в своём физическом списке |
| **Корзина** | Виртуальный | — | Фильтр: `deleted_at IS NOT NULL`. Сюда же уходит «не буду делать» |
| **Пользовательские** | Физический | 100 | Логическая группировка пользователя (до 5 списков) |

Системные списки **не создаются при регистрации** — seed в БД (вариант B: единая таблица `lists`, см. [tasks_tech.md](tasks_tech.md)). Seed — только Inbox.

### Правила членства

- Задача находится **ровно в одном физическом списке** (`list_id`).
- Задача может одновременно попадать в **несколько виртуальных представлений** (например, список «Работа» + «Сегодня» при `due_date = today`).
- «Входящие» — не отдельный флаг: задача во «Входящих», пока её `list_id` указывает на Inbox. Снятие — только **перемещением** в другой список (в т.ч. обратно в Inbox вручную).
- Смена `due_date` / `status` **не меняет** `list_id`.

### Просроченные задачи

Остаются в виртуальном «Сегодня» (если `due_date` = сегодня или раньше — уточнение отображения на фронте). Просрочка **не меняет** бэкенд-логику списков; маркировка — ответственность UI.

### Пользовательские списки

- CRUD: создать, переименовать, удалить.
- Порядок списков в UI — изменяемый (`position`).
- Лимит: **5 списков** на пользователя (удалённый hard delete освобождает слот).
- Лимит: **100 задач** на список (корневые + подзадачи).

### Удаление пользовательского списка

1. Строка списка — **hard delete**.
2. Все задачи списка → **корзина** (`deleted_at`), в `previous_list_id` записывается id удалённого списка.
3. Restore списка **нет**; задачи восстанавливаются **поштучно** из корзины.
4. Если при restore `previous_list_id` указывает на несуществующий список → fallback во **«Входящие»**.

## Создание задач

| Контекст создания | Куда попадает задача | `due_date` |
|-------------------|----------------------|------------|
| По умолчанию / явно «Входящие» | Inbox | опционально |
| Пользовательский список | Сразу в этот список | опционально |
| View «Сегодня» | Inbox | = сегодня (TZ пользователя) |
| View «Следующие 7 дней» | Inbox | = сегодня (default) |

**Запрещено** создавать задачи в: «Выполненные», «Корзина».

Минимальный create: только `title`. Остальные поля — последующим редактированием.

## Статусы и жизненный цикл

### Active

Задача в рабочем состоянии. Видна в физическом списке и подходящих виртуальных view (если не в корзине).

### Completed

- Статус → `completed`, задача **остаётся** в текущем физическом списке («Работа», Inbox и т.д.).
- Дополнительно видна во view «Выполненные».
- Complete родителя → все подзадачи `completed`.
- Задачу можно редактировать в статусе `completed`.

### Корзина (soft delete)

- Любой статус (`active`, `completed`) может попасть в корзину.
- «Не буду делать» = soft delete (отдельного статуса нет).
- `deleted_at` устанавливается; задача **не видна** ни в физических, ни в виртуальных списках (кроме view «Корзина»).
- В `previous_list_id` сохраняется исходный `list_id`.
- Подзадачи — каскад в корзину.
- **Restore:** возврат в `previous_list_id` (или Inbox, если список не существует); подзадачи восстанавливаются вместе.
- **Hard delete:** только из корзины — поштучно или «очистить корзину» (bulk).
- Задачи вне корзины (`completed`) хранятся **бессрочно**; авто-purge не предусмотрен.

## Операции с задачами

| Операция | Описание |
|----------|----------|
| Создать | Title (+ опционально list, due_date) |
| Редактировать | title, description, priority, due_date |
| Переместить | Смена `list_id`: Inbox ↔ пользовательский ↔ другой пользовательский |
| Complete | Статус + каскад подзадач (`list_id` не меняется) |
| Soft delete | В корзину + `previous_list_id` + каскад |
| Restore из корзины | Обратно в `previous_list_id` / Inbox + каскад |
| Hard delete | Только из корзины |

## Дата, время, timezone

- `due_date` хранится в UTC (`TIMESTAMPTZ`).
- Фронт передаёт дату/время **с timezone пользователя**.
- Виртуальные «Сегодня» и «Следующие 7 дней» фильтруют по **календарной дате** в TZ, переданной клиентом (время суток для границ списков не учитывается).
- «Следующие 7 дней»: диапазон **[today, today+7]** включительно.

## Чтение данных (API-уровень, концепт)

Read-only доступ к выборкам задач:

- `GET /tasks/?list_id=` — задачи физического списка (Inbox, пользовательский); `tasks_router` + `TaskService`.
- `GET /views/inbox`, `/views/today`, `/views/next7`, `/views/completed`, `/views/trash` — виртуальные выборки.

Создание: `POST /tasks/` body `{list_id, title, due_date?}` — тоже `tasks_router` / `TaskService`, не nested под lists.

Параметры: **cursor-пагинация** (`limit`, `cursor`), timezone (обязательно для date-views). Технические детали — [tasks_tech.md](tasks_tech.md#пагинация-cursor--lazy-load).

## Пагинация (lazy load)

Ленивая подгрузка на фронте через **keyset pagination (cursor)**, не offset.

### Общие правила

- Пагинируются **только корневые задачи** (`parent_id IS NULL`). Подзадачи — внутри ответа (вложенно) или отдельным `GET /tasks/{id}/subtasks`.
- `tasks.id` — целочисленный `SERIAL`, используется как часть курсора.
- Клиент запрашивает следующую страницу, передавая **`cursor` = id последней задачи с предыдущей страницы**.
- `next_cursor` в ответе — **id последней задачи текущей страницы**, не `cursor + limit` (между id есть пропуски: другие пользователи, другие списки, подзадачи, удалённые).
- `has_more = true`, если вернули ровно `limit` элементов; иначе `has_more = false`, `next_cursor = null`.
- Первая страница — без `cursor`.

### Сортировка по контексту

| Контекст | Сортировка | Зачем |
|----------|------------|-------|
| Inbox, пользовательский список | `created_at ASC`, `id ASC` | Порядок создания внутри списка |
| «Сегодня», «Следующие 7 дней» | `due_date ASC`, `id ASC` | Планирование по дате |
| «Выполненные» | `completed_at DESC`, `id DESC` | Недавно завершённые сверху |
| «Корзина» | `deleted_at DESC`, `id DESC` | Недавно удалённые сверху |

При сортировке по нескольким полям cursor включает оба значения (см. tasks_tech.md).

### Где пагинация обязательна

| Контекст | Лимит данных | Пагинация |
|----------|--------------|-----------|
| Физические списки | макс. 100 задач | опциональна (можно отдать всё), контракт единый |
| Completed, Trash | без жёсткого лимита | **обязательна** |
| Today, Next7 | без жёсткого лимита | **обязательна** |
